# writing-workflow.md：短篇写作工作流详解

本文件包含 story-short-write 的详细工作流程指引。SKILL.md 中只保留摘要和触发条件。

---

## 三阶段审批总览

| 阶段 | 本轮只做什么 | 文件 | 进入下一阶段的条件 |
|---|---|---|---|
| Phase 1 导语选择 | 给 4 组不同故事核的导语，每组附完整故事梗概 | 选定前不落盘；选定后只把导语写入 `导语.md` | 用户明确选中或批准某一版 |
| Phase 2 设计 | 依据已选导语分别写设定与小节大纲 | `设定.md`、`小节大纲.md` | 用户明确批准设计或要求开始正文 |
| Phase 3 正文 | 先把原导语逐字放入成稿，再让第一章现场接棒 | `正文.md`（导语原文 + 数字分节正文） | 9000～12000 字且全部硬门通过后进入 Phase 4 精修 |

阶段门用于避免一开始同时输出导语、人物表、长大纲和正文，导致用户只能整包推翻。除非用户明确要求跳过，任何一轮最多跨过一道用户审批门。

全阶段先读 [story-constraints.md](story-constraints.md)。姓名、主角能动性、单一限知视角、导语原文入正文与现场接棒、9000～12000 字、对话 ≤35%、冲突递进、两节内炸点/爽点、诙谐声线、收费卡点、禁字、禁排比、禁程序化反击和真人感要求属于硬门；与题材包、平台范式或对标书冲突时，以硬门为准。

### 恢复项目时判断阶段

1. 只有题材需求、没有项目目录：Phase 1。
2. 已有 `导语.md`，没有 `设定.md` / `小节大纲.md`：从 Phase 2 开始。
3. 已有设计文件，顶部状态为“待用户确认”：继续修改设计，不创建正文。
4. 两份设计文件均为“已批准，可进入正文”，或本轮用户明确说“开始正文”：Phase 3。
5. 已有 `正文.md`：按用户要求续写或精修，不倒回去重新生成候选。

用户在 Phase 2 实质修改导语时，原设定与大纲随之失效：先更新 `导语.md`，再同步修改两个设计文件并重新等待批准。已有正文时遇到这种修改，不自动重写正文，先说明影响范围。

## Phase 1 导语候选

用户口中的“导言”和本技能的“导语”是同一产物，文件名统一为 `导语.md`。时代未指定时默认现言，平台未指定时默认知乎盐言，不增加一轮选择题。

### 候选输出模板

```markdown
### 1.《暂定标题》

类型：{关系引擎 / 核心钩子 / 情绪口味}

#### 导语

{150-220 字导语}

#### 故事梗概

{250-450 字完整故事链：起因 → 核心关系 / 误会 → 冲突升级 → 关键反转 → 结局}
```

- 默认给 4 组，覆盖不同关系引擎或主要矛盾，例如先婚后爱、身份错认、久别重逢、对立阵营；不要把同一故事只换姓名和职业。
- 每一组都必须有自己的故事梗概，不能四个导语共用一份泛化说明。梗概要写清主角是谁、异常从何而来、关系如何升级、底牌怎样揭开、主要人物最后走向哪里。
- 导语是给读者看的钩子，可以藏底牌；故事梗概是给用户选方向的作者视图，应说透关键反转和结局。两者不能只是长短不同的同一段话。
- 候选阶段不附完整人物档案、分节大纲或写作技法。故事梗概保持因果链，不膨胀成逐节设计。
- 用户要混合两案时，先给一版融合后的最终导语确认；没有得到“就用这版”前仍停在 Phase 1。
- 选中后，`导语.md` 只保存最终导语；不写故事梗概、“候选 2”或审批记录，保证之后可直接接入正文。对应故事梗概迁入 `设定.md`，作为后续大纲的上位约束。
- 每案交付前按 `story-constraints.md` 筛选：主要角色姓名合规；主角有最早主动选择且该选择改变局势；高潮与结局由主角继续推动；无算账、取证、录音、监控、报警、律师或诉讼翻盘。

### 甜宠例文库召回

甜宠候选先读 `example-library/甜宠/README.md` 与 `example-library/甜宠/索引.md`，不要一开始加载 44 篇卡片全文。

1. 按时代、配对、平台口味、男主资源位和目标关系发动机过滤索引；C 级只作边界提醒。
2. 从 A/B 级选 4～8 张候选卡，打开对应的 `未分类.md`、`知乎.md`、`番茄.md` 或 `盐言.md` 阅读完整卡片。
3. 每组新导语最多拿两张卡：一张提供关系发动机，一张提供导语结构，且二者必须属于不同关系发动机。没有合适组合时不用例文卡，回到题材包原创。
4. 先写一句完全脱离样本专有名词的故事核，再设计新人物与新事件；不得从同一篇同时拿职业、高位身份、误会、物件和结局。
5. 四案至少覆盖三种关系发动机。逐案核对人物职业/高位身份、核心误会、关键物件、连续场景链、结尾兑现；与任一卡重合三项即重做。

资料卡是结构证据，不是素材拼贴池。例文与 `story-constraints.md` 冲突时，只记录其为何有效，不召回冲突桥段。

古言 / 现言文风按 `style-benchmarks.md` 路由。每个项目首次生成候选前完整读一次对应原文，后续修改复用项目文风指纹，避免每轮重复加载。

## Phase 2 设计任务（框架确定后执行）

### 开始前先加载 references（逐项检查，不能跳过）

- 全阶段硬约束 → 加载 `story-constraints.md` ✅/❌
- 定题材腔调/招式 → 加载 `genre-styles/{题材}.md` + `short-craft.md` ✅/❌
- 写反派/揭露方式 → 加载 `villain-and-reveal.md` ✅/❌
- 写大纲 → 题材包 `genre-styles/{题材}.md` 的节奏骨架 +（冷门题材）`genre-writing-formulas.md` 速查表 ✅/❌
- 反转信息差验证 → 需加载 `reversal-toolkit.md` ✅/❌
- 伏笔回查 → 见下方「伏笔回查清单」 ✅/❌
- 如某项不适用（如无反派），标注原因后可跳过

### 设计步骤

1. **设计信物 / 贯穿物**（可选，1-2 个）：见题材包招式库「信物翻转」（如追妻火葬场的信物意义翻转）
   - 填写：`- 第1次出现（第X节）：{场景}（{含义}）` 重复三次，含节号定位
2. **设计反派**（如有）：用 villain-and-reveal.md 反派模板
   - 填写：`{身份} + {动机} + {作恶方式} + {致命弱点} + {报应}`
3. **确定揭露方式**：从 villain-and-reveal.md 4 种真相揭露机制中选一种
4. **编写 小节大纲.md**：每节 1 行，格式如下：
   `结构段/五段功能 | 主事件 | 子事件×3-5 | 情绪 | 人物/关系变化 | 因果/逻辑链 | 主角主动动作/造成变化 | 信息来源/视角边界 | 递进关系 | 炸点/爽点 | 读者新获知什么 | 结尾承接/钩子 | 伏笔/物件 | 动静 | 对话预算 | 目标字数`
   - `结构段/五段功能` 使用开头/铺垫/升级/反转/结尾（或起因/发展/转折/高潮/结尾），轻量对应，不要套完整章节蓝图
   - `人物/关系变化` 写本节前后变化；没有显性变化写“无显性，但关系压力/误解/距离变化为…”或 `[待补充]`
   - `因果/逻辑链` 写 `原因 → 行动 → 结果 → 后果/新问题`，避免小节只是情绪堆叠
   - `主角主动动作/造成变化` 必须写主角本节主动做出的选择，以及它改变了什么；连续两节无主动动作即退回重排
   - `信息来源/视角边界` 必须写主角亲眼看见、亲耳听见、亲手读到或后来从谁处得知；“切到对方视角”“作者交代”均不合格
   - `递进关系` 写清本节由上一节哪个结果触发，以及怎样把关系、代价、选择或认知推到更高一层；不能只写“冲突升级”
   - `炸点/爽点` 写具体兑现和关系变化；无则标“无”，但任意连续两节不能同时为“无”
   - `结尾承接/钩子` 写本节如何接下一节；最后一节写结尾落点
   - 子事件必须功能明确（推动剧情/铺垫反转/升级情绪），禁止装饰性子事件
   - 子事件不足 3 个时用扩展规则（加阻碍 / 配角反应 / 移动中发现 / 简短倒叙 / 动作递进；见 short-craft.md 第 10-11 节）
   - 子事件用 `->` 连接，每个子事件包含具体情节点描述+功能标签：
     `具体发生了什么{功能标签}` 如 `发现座位名牌被换了{发现}` / `把戒指冲进马桶{冲突}` / `他笑了{递进}`
     功能标签：`对话` / `冲突` / `伏笔` / `回忆` / `发现` / `递进`
     情节点描述要具体到"谁做了什么"，不能只写标签如`对话`或`冲突`
   - 动静标记：`动` 或 `静` 或 `动静`，相邻两节尽量交替；如因题材需要连续同标记，需确保节内有情绪变化（如：两节都是"静"，但第一节"疑惑→心酸"、第二节"心碎→崩溃"，情绪曲线仍在上升）
   - 对话预算：写预计比例，默认 25%～32%；全文硬上限 35%。不再用“高/中/零”鼓励堆对白；无功能对白直接删
5. **反转信息差验证**（outline 写完后、写作前必须验证）：
   - 回答：读者在第几节知道真相？用「揭穿节号 ÷ 全文总节数」计算位置百分比
     - < 50% → 延迟揭露，反转无效（读者已知真相太早，后续缺少震撼）
     - 50-60% → 灰区，需审视反转力度是否足够（前文误导线索是否充分）
     - > 60% → 反转位置合理（读者等得够久，冲击力最大化）
   - 检查：至少有 1 条读者被成功误导的假线索（不是读者猜到后等角色追上来）
   - 检查：反转前是否铺垫了 ≥3 条指向真相的线索（线索要隐蔽，不是明示）
   - 验证：找一个人（或自我模拟）只看 outline，能否在反转前猜到真相？猜到 = 失败
6. **伏笔回查清单**（outline 写完后、写作前检查）：
   - 列出结尾所有关键元素（物件/信息/角色/关系变化）
   - 每个结尾元素在前文有 ≥1 次铺垫？没有 = 天降，必须补铺垫
   - 贯穿道具三次出现完整？（第 1 次出现在铺垫段，第 2 次出现在反转段，第 3 次出现在结尾段）
   - 铺垫节号与揭穿节号的间距 ≥ 3 节（间距太短铺垫无效）
7. **主角因果链检查**：列出开端、收费卡点、高潮和结局四个节点，逐项回答“主角做了什么才使节点发生”；若删掉主角仍可抵达同一结果，重构。
8. **单一视角检查**：逐节核对 `信息来源/视角边界`；删除他人内心、幕后密谈、主角不在场且事后无来源的场面。题材包允许多视角时仍以本项为准。
9. **收费卡点检查**：位置在全文 30%～50%，停在关键答案前一拍；卡点前不释放核心情绪，卡点后第一场立刻兑现。只把话截半句或门开一半不算有效卡点。
10. **禁用套路检查**：真相与反击不能依赖账目核对、材料汇总、取证、录音、监控、报警办案、律师或诉讼。用主角亲历的选择、对峙、生活细节、角色失误与可见后果推进。
11. **确定性预检**：对 `设定.md` 运行 `node scripts/check-story-constraints.js --kind=design --fail-on=blocking 设定.md`；姓名表或禁用剧情未通过，不得送审。
12. **正文预算预检**：导语字数 + 各节目标字数必须为 9000～12000；任意连续两节至少有一个有效炸点/爽点；逐节递进关系能首尾相接；`设定.md` 已记录导语的诙谐声纹和保持项。

### 写作前加载（硬约束常驻，技法参考同时 ≤ 3 个）

- 必读：`story-constraints.md`（全阶段硬约束）+ `short-format.md`（正文格式）+ `short-craft.md`（通用底座）
- 必读：`short-deslop.md`（写作时自检 AI 腔）
- 按题材加载 1 个：`genre-styles/{题材}.md`（核心 10 题材）或 `genre-writing-formulas.md`（冷门题材速查表）
- 按需加载：`villain-and-reveal.md` / `emotional-methods.md`

### 工作目录结构

工作目录结构见 [Phase 2：设定与小节大纲](../SKILL.md#phase-2设定与小节大纲)。三份文件各管一件事：

- `导语.md`：用户选定的最终导语，只保存读者会看到的文本；Phase 3 将它逐字镜像到 `正文.md` 顶部。
- `设定.md`：顶部写 `> 状态：待用户确认（未批准正文）`，正文包含选中候选的故事梗概、核心框架、主要角色姓名表、人设、主角行动因果链、信息边界、导语声纹、反转铺垫、贯穿道具、反派、题材招式、文风档案与对标摘要；不逐节复述情节。
- `小节大纲.md`：顶部使用相同状态，逐节记录主事件、子事件、因果、主角主动动作/造成变化、信息来源/视角边界、递进关系、炸点/爽点、关系变化、对话预算、钩子和目标字数；不重复整份人物设定。

用户批准后，把两份设计文件的状态更新为 `> 状态：已批准，可进入正文`，再创建 `正文.md`。

### 操作原则

- Phase 1 候选优先在对话中展示，避免为淘汰方案建立目录
- Phase 2 只写三个独立设计文件，不创建空白 `正文.md`
- Phase 3 获批后，先把 `导语.md` 原文逐字写到 `正文.md` 顶部，再从 `1.` 开始写现场接棒的第一章；不要只输出在对话里
- 精修时读取文件再改写，修改记录直接体现在设定.md的贯穿道具追踪中
- 设定.md 维护贯穿道具追踪表：
  `| 物件 | 第1次出现(节号/含义) | 第2次出现(节号/含义) | 第3次出现(节号/含义) |`

## Phase 4 精修打磨

### 精修检查清单

```
## 精修清单

### 开头
- [ ] 前 3 句话能抓住人？
- [ ] 没有无意义的背景介绍？
- [ ] 包含一个开篇钩子？
- [ ] `正文.md` 顶部逐字收录原 `导语.md`，导语后才出现 `1.`？
- [ ] 第一章第一句采用台词回应、动作延续、核心物件、身份反应或女主执行决定之一接棒？
- [ ] 第一章保持导语现场，前三段有新信息，前 500 字完成冲突升级？
- [ ] 除极短关键词/动作桥梁外，没有复述、改写或慢放导语？

### 主角与视角
- [ ] 开端、收费卡点、高潮和结局均由主角的选择触发或改变？
- [ ] 主角没有连续两节只承受、只等待或被他人代为解决？
- [ ] 全文只有单一主角限知视角？
- [ ] 每节关键事实都有主角可以接触的明确来源？
- [ ] 没有直接断言他人内心、幕后密谈或无来源场外事件？

### 情绪
- [ ] 情绪曲线是否有明确走向？
- [ ] 反转前的情绪铺垫够不够？
- [ ] 反转后的冲击够不够？
- [ ] 强情绪由具体代价、关系翻转和主角选择造成，而不是只靠吼叫？

### 主线、递进与爽点
- [ ] 主线能否用一句话复述，是否删除了无关支线？
- [ ] 每个事件都由上一事件的后果触发，冲突在关系、代价、选择或认知上逐级加码？
- [ ] 任意连续两节至少有一个有效炸点或爽点？
- [ ] 后一个爆点是否比前一个改变更多关系、提高更多代价或兑现更大期待？

### 反转
- [ ] 反转是否出乎意料？
- [ ] 反转是否合情合理（回看有铺垫）？
- [ ] 反转时机是否合适？

### 节奏
- [ ] 有没有拖沓的部分？
- [ ] 每句话是否都有存在价值？
- [ ] 字数是否在目标范围内？

### 格式
- [ ] 段落以短为主、有长短交错与疏密变化（非通篇同长度）？无连续超长大段？
- [ ] 段间仅单换行？
- [ ] 对话独立成行、引号风格符合项目/平台约定？
- [ ] 标点节奏匹配语气/人物声线：没有通篇句号化，也没有随机堆砌问号/感叹号，或用 `……`/`——` 硬造停顿？
- [ ] 正文（含对话）里的 `……`、`——`、`—`、`--` 已改成动作、短句、逗号或句号？
- [ ] 无「他说/她道」？
- [ ] 全文含导语为 9000～12000 字？
- [ ] 全文对话比例不超过 35%？

### 钩子
- [ ] 每 2-3 小节有钩子？
- [ ] 章末有钩子（悬念或余韵）？
- [ ] 收费卡点停在关键答案前一拍，足以同时制造愤怒和追读冲动？
- [ ] 收费卡点后第一场立即兑现，没有转场或插回忆拖延？

### AI 腔
```

### 标点确定性收尾

精修后对 `正文.md` 先运行 `node scripts/check-ai-patterns.js --check --fail-on=blocking 正文.md`。blocking 先改正文并复扫；advisory 只作读感提示，确属问题才改，功能性写法标 `[需复核]`。
再运行 `node scripts/normalize-punctuation.js 正文.md`（默认 `--quote-mode keep`）清理无功能省略号、破折号、双连字符和独立分隔线；盐言「」不受影响。

### 删减原则

1. 不推动剧情的对话 → 删
2. 不铺垫反转的描写 → 删
3. 不推高情绪的心理活动 → 删
4. 读者能猜到的内容 → 缩短
5. 重复表达的情绪 → 合并

## 常见问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 开头不抓人 | 在做背景铺垫 | 直接从冲突开始 |
| 中间拖沓 | 信息密度太低 | 删减或合并场景 |
| 反转没力度 | 铺垫不够或太明显 | 增加误导线索 |
| 结尾无力 | 反转后拖太长 | 反转后 500 字内收尾 |
| 全篇平淡 | 情绪曲线太平 | 加大情绪落差 |
| 感觉像流水账 | 缺乏情绪描写 | 加入人物内心感受 |
