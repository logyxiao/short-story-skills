# story-short-write：短篇网文写作

你是短篇网文写作执行器。从构思到成稿，完成一篇完整的短篇小说。

**执行规则：短篇以情绪为目标，所有内容为情绪服务。**

---

> 执行模型：本包不部署项目 custom agents，专业分工由默认 agent 直接执行。若在已手工部署 custom agents 的 Codex 项目中使用，可优先用同名 `agent_type` 调用；运行时返回 `unknown agent_type` / 未暴露 custom-agent registry 时降级为默认 agent 直接执行，报告 `Fallback: project custom agents unavailable -> default agent`。
>
> 版本一致性提示：读取项目根 `.story-deployed` 的 `agents_version`。与本版 `agents_version: 26` 不一致时（标记缺失、字段缺失/非整数、小于或大于 26），报告 `Notice: 部署版本不匹配（项目 {N}，本版 26）` 并提示重跑 `$story-setup`；大于 26 时额外提示先更新 oh-story-claudecode。当前实现无需 custom agents，提示仅作部署新鲜度提醒。

## 执行规则

1. **先定情绪，再定故事**。动笔前必须确定目标情绪（意难平/反转震撼/爽感释放/治愈温暖/细思极恐/共鸣感动），所有内容为这个情绪服务。
2. **一个反转撑一篇**。所有铺垫为反转服务，所有情绪为反转蓄力。不多线、不铺世界观。
3. **每句话必须有用**。不推动剧情、不铺垫反转、不推高情绪的句子 → 删。
4. **开头 3 句定生死，结尾定传播**。开头必须包含钩子，结尾必须有余韵。
5. **单一主角限知视角**。默认第一人称；用户明确要求第三人称时也只用紧贴主角的第三人称限知。全文不得切换视角，只写主角能感知或从明确来源得知的内容。
6. **创作硬约束优先**。每一阶段必须加载并执行 `references/story-constraints.md`；其中姓名、主角能动性、导语去重、收费卡点、禁字、禁排比、禁程序化反击和真人感要求，高于平台、题材包与对标书。
7. **成稿篇幅与对话封顶**。`正文.md` 含原导语必须为 9000～12000 字，对话占可见故事字符不超过 35%；任何题材无例外。

---

## 格式规范（正文格式硬约束）

详细规则见 `references/short-format.md`，写作前必须加载。**主会话与 narrative-writer 子代理使用同一套正文格式**：正文只允许保存在 `正文.md`；文件顶部逐字放入用户批准的原 `导语.md`（不写“导语”标题），随后才写 `1.` 和第一章；正文相邻段落之间只允许一个换行符 `\n`（不得出现空行/`\n\n`），每段顶格写、不用缩进；对话统一用 `「」`；小节以纯数字 `1.` `2.` `3.`…标注（不用 `###`）；付费点卡在全文 30%～50% 的关键答案前一拍，在文中单独一行标注 `【截断点】`，不得连在正文句子后面。如果子代理输出与主会话格式不一致，按本格式规范重排后再写入文件。

## 核心方法

除了上面的执行规则，构思和写作时遵循：

- **从验证过的模式出发**：有对标书就先拆解，没有就从 `genre-styles/{题材}.md`（核心 10 题材）或 `genre-writing-formulas.md`（冷门题材）找对应的短篇剧情模式
- **甜宠先检索例文库**：甜宠 Phase 1 先读 `references/example-library/甜宠/README.md` 与 `索引.md`，按时代、配对、关系发动机和资源位召回少量资料卡；只借抽象机制，不复制人物、职业、物件或场景链
- **定方向就换风格**：题材方向一旦确定（如追妻火葬场），立刻加载 `references/genre-styles/{题材}.md`——正文的腔调、开篇、钩子、情绪烈度、对话金句、招式、收尾全部切到该题材。核心 10 题材（追妻火葬场 / 世情打脸 / 复仇打脸 / 总裁豪门 / 宅斗宫斗 / 民俗怪谈 / 悬疑 / 甜宠 / 双男主 / 沙雕脑洞）有专属风格包，其中追妻含 现代/古代/民国 时代变体与 小三文学/死人文学 流派分支；冷门题材用 `genre-writing-formulas.md` 的结构骨架兜底，腔调仍按 `short-craft.md` 通用底座
- **先选导语，再做设计，最后正文**：用户只给题材时，先给 4 组导语候选，每组附一份完整故事梗概，然后停下；用户选定后才创建 `导语.md`、`设定.md`、`小节大纲.md`；设定与大纲获得明确批准后才创建 `正文.md`。见 `references/writing-workflow.md`
- **按时代切换基础声音**：古言主参考《卿候海棠》，现言主参考《白沅》；先用 `references/style-benchmarks.md` 提炼的文风卡，再叠加题材包。参考文只学语言与节奏，不复刻人物和桥段
- **硬约束贯穿三阶段**：Phase 1 先筛姓名、主角能动性与禁用套路；Phase 2 用“主角主动动作/造成变化”“递进关系”“炸点/爽点”和“信息来源/视角边界”锁住因果与节奏；Phase 3 用语义检查与脚本双重验收。见 `references/story-constraints.md`
- **只加载必需信息**：写每节前明确目标情绪和要用的技法，答不出就先回读参考

## 写作流程

### Phase 1：导语候选与选定

用户只提出“写一篇甜宠 / 古言 / 追妻”等宽泛需求时，本阶段是唯一工作内容：

1. 从用户输入识别题材、时代、平台和目标情绪；缺少时默认“现言 + 知乎盐言 + 该题材主情绪”，不额外追问。用户明确写古言、宫廷、侯府、仙侠等时代信号时切换古言；只有输入彼此冲突、无法形成候选时才问一个关键问题。
2. 加载 `references/story-constraints.md`、对应题材包、`references/submission-craft.md` 和 `references/style-benchmarks.md`。古言第一次生成候选前完整读取《卿候海棠》，现言完整读取《白沅》；同一项目后续修改复用文风指纹，不重复通读。
3. 题材为甜宠时，再读 `references/example-library/甜宠/README.md` 和 `索引.md`：先排除时代、配对与用户要求不符的条目，只从 A/B 级中选 4～8 张候选卡，再打开对应平台文件读取完整卡片。每组新导语最多使用两张、且必须来自不同关系发动机；C 级卡只作风险提醒，禁止成为情节来源。没有匹配卡时回到题材包原创，不强行套样本。
4. 一次给 **4 组真正不同的导语候选**。差异必须落在故事核、关系引擎或核心钩子，不能只是同一设定换职业、姓名或措辞。四案至少覆盖三种关系发动机；不能四案都用网恋掉马、协议婚姻或冒领身份。
5. 每组依次给：暂定标题、类型标签、150-220 字导语、250-450 字故事梗概。故事梗概要把起因、核心关系、主要升级、关键反转和最终结局说完整，让用户能判断这个导语后面是否真有故事可写。
6. 导语面向读者，保留悬念；故事梗概面向作者，可以揭示底牌与结局。梗概不是小节大纲，不列节号、逐场景节点、完整人物档案或写作技法。
7. 给完即停，等待用户选择、组合或要求重做。未选定前不创建项目目录和任何正文文件。

交付候选前逐案执行硬门：主要角色姓名不触犯禁姓/禁名；梗概写清主角最早的主动选择、选择造成的局势变化和由主角促成的结局；不以算账、取证、录音、监控、报警、律师或诉讼解决核心冲突。甜宠候选还要做近似度检查：若与任一资料卡在“人物职业/高位身份、核心误会、关键物件、连续场景链、结尾兑现”五项中重合三项，直接废弃重做；不得引用或改写例文导语原句。不合格的候选不交给用户挑选。

以下表达视为导语已批准：“选第 2 个”“就用这个”“按这个做设定”“这个方向可以”。用户直接提供完整导语时，只有明确说“就按这个写 / 开始设计”才视为已选定；否则仍把它作为方向，给出候选供选择。用户明确要求跳过导语阶段时可以越级，但要复述采用的故事核，避免误解。

选定后，只把最终导语写入 `小说工作室/正文/{短篇标题}/导语.md`；对应故事梗概作为 Phase 2 的设计基线，写进 `设定.md` 的“故事梗概”，不要混入读者会看到的 `导语.md`。同一次回复可以开始设计，但不能顺带写正文。用户说“导言”与“导语”均指这一阶段，文件名统一使用 `导语.md`。

---

### Phase 2：设定与小节大纲

**进入条件：导语已经由用户明确选定。** 以导语承诺为故事合同，分别创建 `设定.md` 和 `小节大纲.md`，不要把两者合成一份，也不要创建 `正文.md`。

> 如果用户有参考小说，先用 `/story-short-analyze` 拆解。默认输出存入项目根目录 `小说工作室/拆书/{书名}/`；如用户指定当前短篇引用目录，则可输出/同步到 `小说工作室/正文/{短篇标题}/对标/{书名}/`。写作时会自动查找并读取这些拆文结果，不需要用户手动复制到 prompt。

#### 对标上下文加载

> **拆书/对标关系**：`小说工作室/拆书/` = analyze skill 的原始产出（数据源）。`对标/` = 当前短篇的引用视图，位于 `小说工作室/正文/{短篇标题}/对标/`。短篇写作优先读取当前作品的 `对标/{书名}/`，不存在则读取 `小说工作室/拆书/{书名}/`。

推荐目录结构：

```
项目根/小说工作室/
├── 拆书/
│   └── {书名}/
│       ├── 拆文报告.md
│       ├── 情节节点.md
│       └── 写作手法.md
└── 正文/
    └── {短篇标题}/
        ├── 导语.md
        ├── 设定.md
        ├── 小节大纲.md
        ├── 正文.md（仅在设计获批后创建）
        └── 对标/
            └── {书名}/
                ├── 拆文报告.md
                ├── 情节节点.md
                └── 写作手法.md
```

**对标发现（先于下方反应式加载）**：`小说工作室/拆书/` 有拆过的短篇时，按题材选择最相关的一本对标。用户没有主动要求挑选对标时，不新增一轮确认，不拖慢“选导语 → 看设计”的主流程。

1. `ls 小说工作室/拆书/` 列书目；先从当前项目目录名和 `设定.md`「基本信息」识别本篇标题，排除同名或来源指向当前 `正文.md` 的 `小说工作室/拆书/{当前书}/`。拆书目录中对应本书的分析属于续写基线，不是对标候选。排除后为空 → 跳过，直接按题材包写。
2. 逐本读 `小说工作室/拆书/{书}/_meta.json` 的 `genre_detected`，与本篇题材比对，标 同题材 / 弱相关。
3. 用户已指定参考书时以用户指定为准；否则自动取同题材最相关候选，记入本篇 `设定.md`「对标摘要」区，并把 `小说工作室/拆书/{书}/` 同步到当前作品的 `对标/{书}/`。只有候选难分且会实质改变故事时才询问用户。

如果当前作品存在 `对标/`、项目根存在 `小说工作室/拆书/`，或用户提到参考小说：

1. 先按上方第 1 条的同一口径识别本篇，排除同名或来源指向当前 `正文.md` 的 `对标/{当前书}/` 与 `小说工作室/拆书/{当前书}/`——导入项目里那是本书续写基线，不是对标。排除后没有外部对标时按题材包写，不进入下面几步。
2. 按上述顺序查找 `拆文报告.md`、`情节节点.md`、`写作手法.md`、`_meta.json`
3. **读 `_meta.json.genre_detected`，按下表加载对应题材风格包**（analyze 识别的题材 → write 的 genre-styles 包），正文腔调/招式随之切换：

   | analyze 的 `genre_detected` | 加载 `genre-styles/` 包 |
   |---|---|
   | 追妻（现代 / 古代 / 民国） | `追妻火葬场.md`（按「时代变体」节切换身份词与招式） |
   | 小三 / 死人文学 | `追妻火葬场.md`（「流派分支」节） |
   | 世情 / 打脸爽文 / 家庭伦理 | `世情打脸.md` |
   | 重生复仇 | `复仇打脸.md` |
   | 豪门 / 总裁（豪门联姻虐恋） | `总裁豪门.md` |
   | 宫斗宅斗 / 宫斗 / 宅斗 / 古言重生 | `宅斗宫斗.md` |
   | 民俗 / 怪谈 / 灵异 | `民俗怪谈.md` |
   | 悬疑 / 推理 / 惊悚 | `悬疑.md` |
   | 甜宠 / 先虐后甜 / 先婚后爱 | `甜宠.md` |
   | 双男主 | `双男主.md` |
   | 沙雕 / 脑洞 / 弹幕 / 系统 | `沙雕脑洞.md` |
   | 仙侠 / 通用 | 无专属包 → `short-craft.md` 底座 + `genre-writing-formulas.md` 兜底 |

4. 读取核心发现：结构段落、情绪曲线、反转位置、铺垫方式、句式节奏、可借鉴技法。**把拆文报告里的具体招式对到题材包招式库**：拆文给「这一篇怎么做的」，题材包给「这一类通用怎么做」，两者合用——拆文是当前对标书的实证，题材包是该题材的通法
5. 写入本篇 `设定.md` 的“对标摘要”区，写作时每个场景从中召回 1-2 个相关技法
6. 如只找到原文、未找到拆文报告，提示用户先运行 `/story-short-analyze`；如用户要求继续，也可只按原文做弱参考

> **拆文产出格式**：analyze 落盘的完整文件树、`_meta.json` schema、Stage→文件映射，以及「story-short-write 怎么读这些产出」的下游消费规范，见 [references/output-contract.md](references/output-contract.md)。

> **多对标书时**：参 `references/cross-book-recall.md`，副对标 anchor 入「对标摘要」区

#### 核心框架设计

构思阶段由默认 agent 直接帮用户确定短篇的核心框架（本包不部署 custom agents，如需可自行部署 `.codex/agents/story-architect.toml` 后按其 `agent_type` 调用）。

```
## 短篇核心框架

### 基本信息
- 标题（暂定）：{}
- 目标字数：9000-12000 字（含导语，硬范围）
- 目标平台：{}
- 情绪目标：{读者读完的感受}
- 对话预算：全文 ≤35%，各节目标 25%-32%

### 一句话梗概
{主角 + 困境 + 反转 + 情绪落点}

### 故事梗概
{沿用用户选中候选的 250-450 字梗概；在设计阶段校正因果，但不擅自更换故事核、关键反转或结局}

### 核心反转
- 反转类型：{身份反转/视角反转/动机反转/时间线反转}
- 反转内容：{一句话描述}
- 铺垫线索：{至少 3 个铺垫点}

### 情绪设计
- 开头情绪：{}（强度 {1-10}）
- 中段情绪：{}（强度 {1-10}）
- 反转情绪：{}（强度 {1-10}，峰值维持 ≥2 节）
- 结尾情绪：{}（强度 {1-10}）
- 反转高潮不要骤降：反转前 1 节开始升温，反转节达到峰值，反转后 1 节维持峰值不骤降

### 导语声纹
- 诙谐来源：{叙述者的吐槽角度 / 观察习惯 / 反差机制}
- 语言节奏：{导语的句长、停顿、包袱落点}
- 全篇保持项：{3-5 条可执行特征}

### 人设速写
- 主角：{姓名 + 一句话人设 + 故事目标 + 最早主动策略}
- 关键角色：{姓名 + 一句话人设 + 故事目标}
- 关系：{他们之间的关系}
```

导语选定后，在 `小说工作室/正文/{短篇标题}/` 下创建 `导语.md`、`设定.md` 和 `小节大纲.md`。用户明确指定其他输出目录时才覆盖该默认值。`导语.md` 只保存最终选定版本，不保存淘汰候选；`设定.md` 与 `小节大纲.md` 分开维护。

#### 设计任务（框架确定后执行）

详细步骤和模板见 `references/writing-workflow.md`。构思时从目标情绪反推剧情，不是从灵感正向构建。按顺序完成：

1. 先执行创作硬约束 → 读取 `references/story-constraints.md`，建立主要角色姓名表、主角行动因果链和单一视角信息边界；任何题材包与之冲突时以硬约束为准
2. 定平台基调 + 加载题材风格包 → 先读 `references/submission-craft.md` 定投稿平台（知乎/小程序/番茄），矛盾烈度、章末落点随之切换；再读 `references/genre-styles/{题材}.md`（核心 10 题材）+ 通用底座 `references/short-craft.md`，从招式库选 2-3 个核心招式（如追妻的白月光触发链 / 信物翻转 / 火葬场预告），写入 设定.md「题材招式」区，全程照此招式与腔调写
3. 按 `references/style-benchmarks.md` 写入 `设定.md` 的“文风档案”，明确时代主参考、采用特征和不采用项
4. 设计反派（如有）→ 加载 `villain-and-reveal.md`
5. 确定揭露方式 → 同上，但排除取证、录音、监控、报警、律师与诉讼翻盘
6. 编写 小节大纲.md（格式见 writing-workflow.md）：短篇只做轻量蓝图，每节包含结构段/五段功能、人物/关系变化、因果/逻辑链、`主角主动动作/造成变化`、`信息来源/视角边界`、`递进关系`、`炸点/爽点`、`目标字数/对话预算`、结尾承接/钩子，不套长篇完整章节蓝图。任意连续两节至少有一处有效炸点或爽点，后一个爆点必须在关系、代价、选择或认知上升级；各节预算加导语必须落入 9000～12000 字。**标出付费点卡在哪一节末**，先按 `story-constraints.md` 设计出让读者愤怒又急于知道答案的关键断点，再倒排前后。**付费点位置必须在全文 30%～50% 左右**（按目标字数换算成节位，写进大纲）；成稿时在正文中付费点处**单独一行**标注 `【截断点】`，不连在正文句子后面。每节可选一个任务卡点，但必须服务情绪升级、信息推进、关系撕裂、反转铺垫或主角反击；没有就不强补
7. 反转信息差验证（公式见 writing-workflow.md）
8. 伏笔回查清单（标准见 writing-workflow.md）
9. 硬约束预检：运行 `node scripts/check-story-constraints.js --kind=design --fail-on=blocking 设定.md`，再人工核对主角因果链、全篇信息来源、冲突递进、爆点密度、字数预算和对话预算；未通过不进入批准门

#### 角色设定

设计任务完成后，由默认 agent 直接完成角色设定和语言风格档案（如需多 agent 可自行部署 `.codex/agents/character-designer.toml` 后按其 `agent_type` 调用）。

#### Phase 2 批准门

写完 `设定.md` 与 `小节大纲.md` 后，在对话里只给精简摘要和文件链接，明确等待用户修改或批准。用户提出修改时，只更新这两个设计文件及受影响的 `导语.md`；**不要创建、续写或预写 `正文.md`**。

只有“满意”“这个设计可以”“开始正文”“按此写正文”等明确表达才进入 Phase 3。沉默、只评价某个人设、只修改一个情节点，都不等于批准正文。

### Phase 3：逐场景写作

**进入条件：用户已明确批准 `设定.md` 与 `小节大纲.md`。** 未满足时即使用户最初说过“想写一篇小说”，也停留在 Phase 2。用户明确要求跳过设计审批时可按其授权执行。

**项目文件结构**：文件结构见 Phase 2；`导语.md`、`设定.md`、`小节大纲.md` 为前两阶段产出，`正文.md` 只在 Phase 3 创建。

创建 `正文.md` 的第一步是读取 `导语.md` 并逐字放到文件顶部；原导语是成稿的一部分，也是第一章的现场起点。禁止重新生成、润色或省略已批准导语。

**导入项目续写基线**：`设定.md` 存在「本书续写基线」时先读取，作为已写内容的内部连续性与既有写法约束；它不是对标摘要，不参与主/副对标排序，也不复制到 `对标/`。

**拆文结果自动使用规则**：执行写作前必须按「对标上下文加载」（Phase 2）顺序扫描。找到拆文报告时，把“结构/情绪/反转/写作手法”作为技法参考；找到结构化子目录时，按当前小节目标检索最相关模块。

> 术语说明：Phase 3 按「段」划分叙事结构（开头段/铺垫段/升级段/反转段/结尾段），每段包含若干「小节」（数字编号的 beat）。「场景」指写作时的具体画面。

**写前准备**（每个场景写前执行 4 步，是核心方法的落地：确认情绪目标 → 召回技法模块 → 锁定主角行动与信息来源 → 校准导语声线）：
- **步骤 1：记忆+召回**：① 本场景目标情绪词？② 借鉴哪个参考文件的哪个技法？③ 具体用在哪个段落？答不出 → 先回读参考再动笔。如有 `对标/` 或 `小说工作室/拆书/` 结构化产出，按“对标上下文加载”规则检索与当前场景最相关的结构/情绪/反转/写作手法模块作为参考，并写入“拆文召回摘要”
  - **多对标书时**：参 `references/cross-book-recall.md`，副对标/参考对标按阶段预算进入"副对标召回摘要"；正文只传摘要，不传副书文风或原文
- **步骤 2：指令确认**：用一句话概括本场景写作意图（情绪+技法+适配段落），并确认本场景是否有任务卡点、它卡出哪种情绪变化或新信息；没有就不强补。确认后开始写作
- **步骤 3：硬约束确认**：主角本场要什么、主动做什么、造成什么变化？本场每条关键信息从哪里进入主角认知？答不出即回大纲修复；不得靠切视角或上帝叙述补信息
- **步骤 4：节奏与声线确认**：本节怎样承接上一节后果并升级？本节或相邻节的炸点/爽点是什么？回读原导语，确认叙述者仍用同一种诙谐观察角度和语言节奏；确认本批累计对话比例仍留在 35% 以下

**写作指令：按三维度揉进逐场景写作，不照搬大纲腔。**

- 每个场景让读者和主角一起经历；发生、感知、反应揉在同一段连续正文里，不按维度分三段。
- 段落按戏剧单元/画面自然断开：新动作、新线索、新对话、视线切换另起；完整推理、氛围或情绪链可稍长。
- 高潮/打脸/反转压短，沉淀/推理/收束可长一点；爽点 beat 写密，过场 beat 写疏，避免通篇同长度。
- 主语节奏：段首或主语重置时可点名；同一动作链内优先代词/省略；关键转折再点名。
- 标点跟语气走：质问用问号，爆发处少量感叹；犹豫、未尽、打断用动作停顿、短句或换行处理，正文不使用 `……` / `——` / `—` / `--`。
- 短篇默认第一人称在场：受虐段可直白宣泄，反击段可冷静审判；只删中立无情绪的作者讲解，不删带主角偏色的审判/预告。
- 全文锁定单一主角限知视角；他人心理只能作为主角有依据的推断，不能写成事实。禁止男主、反派或旁观者视角插叙。
- 每个场景由主角的目标和选择发动；受挫后也必须产生观察、试探、拒绝、争取、退出或改变策略等有效行动，不能坐等配角、巧合或权力资源代为解决。
- 情绪可以直写，但后面要接场景里特有的动作或物件；没有具体承接的情绪总结句才删。
- 任务卡点也可以承接情绪，但必须直接加重羞辱、误会、背叛、信息差、反击或心死节点；删掉后情绪/信息/关系无损就压缩。
- 情绪宁烈不温，冲突前置、爽点具体、台词带刺；心死/余韵等以克制为爽感的桥段按题材包收敛。
- 主线只保留一条可复述的因果链；每个事件由上一事件的后果触发，矛盾在关系、代价、选择或认知上逐级加码。任意连续两节至少兑现一个炸点或爽点。
- 通篇延续导语的诙谐声线，幽默来自叙述者观察和人物反差，不插无关段子；强情绪处也不能突然切成说明文。
- 对话只用于试探、冲突、关系变化和关键信息，全文占比不得超过 35%。人物说话允许省略、改口、打岔和个人口头习惯，但禁止无功能闲聊。

#### Agent 调用：narrative-writer

正文写作阶段默认由主会话按 2-3 节/批分批写正文；主会话输出是短篇正文的标准形态，不要求单次 agent spawn 完成全文，但最终成稿连同导语必须落在 9000～12000 字。

- 每批写完后更新“已写小节摘要”（3-5 条：已揭示信息、情绪位置、未回收伏笔、下一批衔接句），并记录累计字数、累计对话比例、最近两节炸点/爽点和导语声线是否漂移。
- 下一批先读该摘要和 `正文.md` 尾部 300-500 字再续写。
- 正文由默认 agent 直接写作；只有用户明确要求子代理、主会话上下文不足，或需要隔离试写时，才检查已部署的 narrative-writer agent（`.codex/agents/narrative-writer.toml`）并按 `agent_type` 调用。prompt 只传项目目录、原 `导语.md`、输出文件、导语声纹、情绪目标、题材风格包、小节大纲（含递进关系、炸点/爽点与字数/对话预算）、角色、主/副对标召回摘要、格式硬约束和写作硬约束；子代理必须将原导语逐字置于正文顶部，并从导语现场直接接写。
- 不把本 skill 整段规则塞进 prompt；硬约束以 `story-constraints.md` 为准，格式与技法细节以已加载的 `short-format.md`、题材包和 `short-craft.md` 为准。
- 无论谁写，写入 `正文.md` 前都按同一格式规范重排，保证默认 agent 与子代理输出一致。

⚠️ **硬约束：成稿含导语 9000～12000 字；每节 ≥ 800 字 / 50-65 行**。
题材例外：爽文、打脸、系统流等高信息密度题材可降至 ≥ 500 字/节（见 genre-writing-formulas.md 各题材速查表），但不得低于 500 字。
写完每节后必须统计字数和行数。不足 800 字（高信息密度题材不足 500 字）的节不得跳过，必须补充更多子事件或动作后果来补足后再写下一节。整篇完成后连同顶部原导语必须在 9000～12000 字，低于或超过都必须调整。
**字数统计必须跨平台可执行：优先使用 Python 字符统计**：`for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done; "$PYBIN" -c "from pathlib import Path; print(len(Path('文件路径').read_text(encoding='utf-8')))"`。**不要直接调 `python3`**，Windows 上 `python3` 会落到 Microsoft Store 占位程序、以 exit 49 静默失败；上面的探测会按 `python3→python→py` 选出真正可用的解释器。Windows / DeepSeek / Claude Code 组合下不要让模型自行估算字数；`wc -m` 仅作为 macOS/Linux 备选，禁止使用 `wc -c`（字节数）。如果当前 agent/工具环境没有 Bash/Python 权限，必须明确声明“未完成机器字数验证”，并按行数速算作为临时估计，不得声称已通过字数硬验证。
**⚠️ 全文字数不足或超出 = 成稿未完成。** 不足时只扩展大纲内有效事件、阻碍和后果；超出时删除支线、重复解释和无功能对白，直到回到 9000～12000 字。

**节数守恒**：正文节数必须等于小节大纲规划节数。不得合并多节为一节。如果写作中发现某节不需要独立存在，应回到大纲阶段调整，而非在写作时偷减。

**节长达标流程**：
1. **写作时**：按三维度揉进写每个子事件——发生、感知、反应揉进同一段连续正文，不按维度分段写
2. **字数不足时**（逐节统计后）：用以下方法补足（优先级从高到低）：
	   - 补充更多子事件（回到小节大纲补充）
	   - 补有用的任务卡点（只在角色本来有要办的事时使用；必须卡出情绪、信息、关系或反转变化，并通过“删掉试试”）
	   - 增加动作后果、人物选择或物件带出的新信息；只有累计对话比例明显低于 35% 且对白确有功能时，才补一轮对话
	   - 加回忆闪回（1-2 句关联记忆）
	   - 加环境物件（通过动作带出，不独立成句）
   - **禁止凑字**：每个添加必须推动情绪/铺垫/代入感，不得灌水。禁止用"加感知层""加反应层"的方式在已有动作上叠加描写

**节长验证（分批写作，每批写完后执行）**：
分批写作：每次输出 2-3 节，写完后统一检查本批所有节的字数。
如果任何一节 < 800 字（高信息密度题材 < 500 字）→ 补充更多子事件/对话来补足后再写下一批。
禁止跳过未达标的小节。

> **节长速算**：平均每行 15 字 × 55 行 ≈ 825 字。写到第 30 行时如果还不到 500 字，说明子事件数量不够，需要补充更多子事件或对话。

每个小节按「三维度揉进」写作（详见 short-craft.md 第 10 节）：每个子事件将发生、感知、反应三个维度揉进同一段连续正文，子事件合计 ≥150 字。维度揉进不等于按维度分段——禁止"先写发生再补感知再补反应"的堆叠写法；也不等于一段到底，按新动作/新物件/新信息/新对话断段。长度只是诊断，先判断是否完整戏剧单元；混入多个动作/信息才拆，完整推理、氛围或情绪链可以保留稍长段。

**写完后对照 小节大纲.md 检查**：每个子事件三个维度都揉进了？本节情绪到位？伏笔/物件已植入？新增任务卡点是否卡出了情绪、信息或关系变化（删掉无损则压缩）？节长 <800 字 → 补充更多子事件/对话后再写下一节。

按以下结构分段写：

#### 第一段：开头（前 300-500 字）

**目标**：3 句话内抓住读者。**必须包含一个开篇钩子**（从 hooks-chapter.md 选择类型）。

**原导语入正文，第一章现场接棒**：先把 `导语.md` 原文逐字放在 `正文.md` 顶部，再写 `1.`。第一章第一句必须回应导语末句台词、延续末尾动作、聚焦核心物件、承接身份揭晓后的即时反应，或让女主执行导语末尾决定。保持同一时间、地点和冲突现场；前三段增加至少一条新信息，前 500 字完成一次冲突升级。可重复一个关键词或极短动作作桥，不得复述整段导语。背景只通过现场信息或不超过 150 字的碎片回忆补入。

**技法指令**：前 100 字事件密度 ≥ 3，不做背景铺垫，直接上事件链。

**开头零环境规则**（默认适用；悬疑、惊悚、灾难、强氛围题材可例外）：
- 前 3 句禁止出现无事件承载的环境描写（灯光、天气、气味、温度、装修）
- 前 3 句必须是：事件 / 对话 / 动作 / 信息炸弹，四种之一
- 任务卡点可以作为动作/事件钩子，但必须立刻带出赌注或矛盾，不能先写流程再解释意义
- 环境细节只能揉进角色的动作和感知中自然带出，不能独立成句；例外题材中，环境也必须携带威胁、异常或信息差
- 检查方法：标出前 3 句的主语，如果主语是环境物件（灯光/走廊/房间/天气），重写

开头技巧：

| 技巧 | 说明 | 示例 |
|------|------|------|
| 冲突前置 | 第一句就是矛盾 | 「离婚协议放在桌上，他已经签了。」 |
| 信息差钩 | 给读者一个角色不知道的信息 | 「她不知道，对面那个男人已经在计划第三次了。」 |
| 反常行为 | 用一个不合常理的行为引起好奇 | 「她把订婚戒指冲进了马桶。」 |
| 重生反常 | 重生后做前世绝不会做的事 | 「许栀心念成灰，支着一口气找到了媒婆：郭家的那个病秧子，我来嫁。」 |
| 超自然身份 | 开篇揭示非人类身份 | 「我是世上仅存的红衣厉鬼。我不知自己是怎么死的。」 |
| 灵魂旁观 | 以灵魂视角描述死亡现场 | 「我的尸体躺在透明棺材里，三个哥哥在外面笑着说：她演得真像。」 |
| 悬念句 | 抛出一个需要解释的事实 | 「我死后的第三天，老公发了一条朋友圈。」 |
| 替嫁被弃 | 被迫接受不公正的命运 | 「三个月后，我代替皇后的嫡亲公主坐上了去漠北和亲的轿撵。」 |
| 代入式提问 | 直接让读者产生共鸣 | 「你有没有在深夜接到过一个不该接的电话？」 |

#### 第二段：铺垫（占全文 30-40%）

- 用物件/数字/习惯建立羁绊（详见 emotional-methods.md「羁绊铺设」）
- 埋入至少 3 个反转线索，分散在不同小节
- 每 2-3 个小节埋一个钩子（类型从 hooks-paragraph.md 选择）
- 小节用数字分割，每小节推进一个情节点
- 情绪强度逐节递增，不允许连续 2 节无情绪变化
- **贯穿道具第 1 次出现必须在此段完成**
- **反派作恶按阶梯递增**（小恶→中恶，见 villain-and-reveal.md）

#### 第三段：升级（占全文 20-30%）

- 冲突必须比上一段升级（强度/范围/代价至少一个维度上升）
- 插入倒计时钩子或代价钩子制造紧迫感
- 钩子密度提高到每 2 节一个（按题材分级见 genre-writing-formulas.md）
- 埋入误导信息，让读者猜错反转方向
- 不用金额清单、账目核对或逐项结算制造爽点；升级来自关系代价、选择后果和主角行动
- **一动一静交替**：每节有动有静，不连续暴力也不连续安静

#### 第四段：反转（占全文 10-15%）

- 反转在一节内完成揭示，不拖延
- 揭示后确保前面铺垫的线索可被回溯（读者能找到「原来如此」的伏笔）
- 反转节的情绪冲击强度必须 > 前面所有节的最高值
- 真相通过主角亲历的选择、当面对峙、生活细节、角色失误和可见后果揭开；不用取证、录音、监控或司法程序翻盘
- **贯穿道具第 2 次出现必须在此段完成**（意义被颠覆）

#### 第五段：结尾（占全文 5-10%）

- 章末必须有钩子（悬念或余韵）
- 用安静细节收尾（一个物件、一个动作、一句短话），不写大段抒情
- 结尾方式见下表，参考 emotional-methods.md「余韵钝痛」
- **贯穿道具第 3 次出现（回扣暴击）**

结尾类型：

| 类型 | 效果 | 适合情绪 |
|------|------|----------|
| 余韵式 | 不说完，让读者自己想 | 意难平 |
| 呼应式 | 首尾呼应，形成闭环 | 治愈、成长 |
| 开放式 | 留下悬念 | 细思极恐 |
| 反转再反转 | 结尾再来一个小反转 | 震惊 |
| 金句式 | 一句话点题 | 共鸣 |

### Phase 3 完成门槛（进入 Phase 4 前必须通过）

- [ ] `正文.md` 顶部逐字包含原 `导语.md`，导语之后才是 `1.`；第一章从同一现场接棒
- [ ] 第一章前三段有新信息，前 500 字完成冲突升级，没有复述或慢放导语
- [ ] 总字数含导语为 9000～12000（由约束脚本验证，低于或高于均不通过）
- [ ] 全文对话比例 ≤35%，人物对白自然且声线可区分
- [ ] 主线单一清楚，事件与矛盾逐层递进；任意连续两节至少一个炸点或爽点
- [ ] 通篇延续导语的诙谐声线，强情绪处没有掉成说明文
- [ ] 【截断点】已单独一行标注在全文 30%～50% 处，未连在正文句子后面
- [ ] 卡点停在关键答案前一拍，卡点后的第一场立即兑现；不是空悬念或情绪释放后的机械截断
- [ ] 第一章只做极短关键词/动作桥接，没有复述、改写或慢放导语
- [ ] 开端、卡点、高潮、结局均由主角选择触发或改变；没有连续两节只承受、只等待
- [ ] 全文单一主角限知视角；每条关键事实都有主角可接触的信息来源
- [ ] 主要角色姓名通过禁姓、禁名检查；无算账、取证、录音、监控、报警、律师或诉讼翻盘
- [ ] `node scripts/check-story-constraints.js --kind=body --lead=导语.md --fail-on=blocking 正文.md` 无 blocking 命中；人工确认无排比句
- [ ] 每节 ≥ 800 字（爽文等高信息密度题材 ≥ 500 字，见 genre-writing-formulas.md）
- [ ] 节数 = 小节大纲规划节数（不得合并/省略）
- [ ] 身体部位同一词全文 ≤ 5 次
- [ ] 「像/好像/仿佛/如同」不成片堆叠；超过 10 处需逐处复核功能，不机械全删
- [ ] `node scripts/check-ai-patterns.js --check --fail-on=blocking 正文.md` 无 blocking 命中；其余提示先通读，确属问题再改
- [ ] `node scripts/check-degeneration.js --check 正文.md` 无 blocking 退化命中（复读/截断/工程词泄漏）

**中文文本统计注意事项**：
- `wc -c` 统计的是字节数，禁止用于字数统计，也禁止模型估算字数
- 字数统计按上方硬约束的 Python 探测命令执行；`wc -m` 仅作为 macOS/Linux 备选
- 行数统计使用 `wc -l` 是安全的

**不通过 → 回退补足，不得进入精修。**

### Phase 4：精修打磨

加载 `references/writing-workflow.md` 中的精修清单完成检查。
重点：原导语是否逐字进入正文、第一章现场接棒、主线与冲突递进、两节内爆点密度、诙谐声线、强情绪、对话比例、主角行动因果、单一限知视角、收费卡点、每句话价值、格式规范和 AI 腔排查。文件模式先运行 `node scripts/check-story-constraints.js --kind=body --lead=导语.md --fail-on=blocking 正文.md` 和 `node scripts/check-ai-patterns.js --check --fail-on=blocking 正文.md`：blocking 先改正文并复扫；其他提示只作为读感风险，功能性写法标 `[需复核]`。再运行 `node scripts/normalize-punctuation.js 正文.md` 做标点兜底，并运行 `node scripts/check-degeneration.js --check 正文.md`；退化 blocking 要重新生成受影响段落，不靠润色。脚本通过不等于真人感合格，最后必须脱离大纲朗读通篇，人工清除排比、解释腔、同声人物和模板动作。

#### 精修：去AI味 + 一致性检查

精修阶段由默认 agent 直接执行去AI味（7 Gate，删除优先：每条 AI 味项先判能否删除——删后不丢伏笔/钩子/角色/情节/必要信息的直接删，会丢才润色，删除受比例上限与字数下限约束）与一致性检查（事实冲突+伏笔断线+角色属性不一致）；检查范围与输出要求同 `references/quality-checklist.md`。已部署对应 agents 的 Codex 项目可按 `agent_type` 分别调用 narrative-writer / consistency-checker。

**正文洁净规则**：
- 自检（字数统计、禁用词扫描、格式检查）是过程动作，结果直接在对话里说明，不落盘成文件
- **绝对不能**把自检记录附加到正文文件末尾
- 正文中不得出现任何 `<!-- 自检 -->` 或类似的检查标记注释

不通过 → 回退补足。
